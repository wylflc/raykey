# 仓库清理规则

用户要求清理仓库、精简文档或删除不再需要的文件时，按本文件执行，不需要用户重新说明。`docs/xzy/` 不读、不改。

## 1. 文档内容边界

| 文件 | 只写 | 删去或移到落点 |
| --- | --- | --- |
| 工作流程、个人投资体系 | 现行命令、参数、阈值、公式、步骤、路径、输入输出与失败处理 | 理由与动机、个股举例、读数、版本与日期沿革、`OI-` 编号、实验证据指针、研究开关的逐项说明、别处已定义规则的复述 → 版本记录、回测日志或报告 |
| 评分细则 | 四维打分方法与证据字段 | 层级与交易规则（读工作流程） |
| 待处理事项 | 未完成项，每项一个三级标题 | 结案经过 → 结案索引一行 |
| 结案索引 | 每项一行：编号、主题、处置、结案版本、详见 | 过程叙述 |
| 版本记录 | 每版一行：规则变化与落点、依据节号 | 读数、过程、用户原话 |
| 回测日志 | 每节 ≤ 1.5 KB：测了什么、结论、参考读数、裁定与落地、实验目录 | 整表 → `data/experiments/<目录>/` |
| 每日扫描日志 | 未归档条目 | 上月及更早条目按工作流程 §9.1 第 6 步归档 |
| README、CLAUDE.md、各目录 README | 入口、索引与指针 | 规则正文、结果与阈值 |

精简工作流程与个人投资体系时：

1. 同一规则只在定义处写一次，其他位置只写「见 §x」；交易阈值只在工作流程 §9.3.1。
2. 生产参数只写命令与取值；脚本的其他取值由工作流程 §6.7 统一约束，不逐项写「只作复现」。
3. 被测试逐字校验的条文保持原样。修改前运行 `grep -n "docs/000_Ashare_workflow.md" scripts/test_*.py` 找到这些测试，确认其断言文本；确需改写时同批改测试。
4. 正文有改动即第 1 行版本号进一位、版本记录加一行；只删改文字时写「文档精简，规则不变」。

## 2. 文件处置

| 类别 | 判定 | 处置 |
| --- | --- | --- |
| 一次性作业 | `scripts/slurm/` 中只服务一个已结案事项或已落地版本的作业 | 移入 `scripts/archive/slurm/`，在 `scripts/archive/README.md` 登记归档日与可永久删除日（归档日加三个月） |
| 退役脚本 | 工作流程未引用、无未归档脚本调用、产物已被取代或所属轮次结束，三条同时成立 | 移入 `scripts/archive/`，同上登记 |
| 到期归档 | `scripts/archive/README.md` 的可永久删除日不晚于今日 | 删除文件与索引行；只被这些脚本读取的数据一并删除 |
| 重复报告 | 内容已在现行文档中，如每日扫描回复已写入扫描日志 | 删除 |
| 过程记录 | 仓库审计与清理记录、事项状态快照、交接说明、方案草稿、外部审核意见；所涉事项已结案、结论已入日志 | 删除 |
| 历史全文副本 | `docs/archive/` 中的旧文档与旧纪元日志 | 删除，`docs/archive/README.md` 登记取回命令 |
| 派生产物 | 可由脚本重建的回测与估值中间件 | `python3 scripts/clean_derived_artifacts.py` 预览后加 `--apply`；已结案实验用 `closed` |
| 作业日志 | `logs/` 中 14 天前的文件 | `find logs -type f -mtime +14 -delete` |

保留：实验与决策证据（实验报告、修复核验、口径分析）、公司研究、`data/experiments/` 中被日志引用的证据、`data/companies/`、`docs/peer-group-calibration/`、原始数据、结构化真值、决策日志与账户台账。

## 3. 引用核对

删除或移动前，用 `git grep -l -F <文件名>` 查已跟踪文件中的引用：

- 阻止删除的引用：现行文档（README、CLAUDE.md、工作流程、个人投资体系、评分细则、待处理事项、核心池阅读版、各目录 README）、`scripts/` 中未归档的代码、`data/processed/` 与 `data/reference/` 的结构化数据、`.gitignore`。先改引用，改不了就保留文件。
- 不阻止删除的引用：决策日志、版本记录、回测日志、结案索引、扫描日志、报告、归档文件与 `data/experiments/` 中的记录。它们保留当时路径，按第 5 节取回。
- `data/processed/daily_execution_publication.json` 列出的输入与产物（含决策日志）不得改动，否则当日执行清单失效；只删改文档时不写决策日志。

## 4. 执行与校验

1. `git status` 干净；`squeue -u "$USER"` 无相关作业。
2. 先改现行文档，再删除或移动文件，最后修正引用与目录索引。
3. 运行 `python3 scripts/audit_repository_docs.py` 与第 1 节第 3 条找到的测试；改动档案模板时加 `python3 scripts/build_company_dossier_readmes.py --check`。审计报错（ERROR）覆盖：执行文档中的 `OI-` 编号与「只作复现」、待处理区的叙述、回测日志超长节、`docs/archive/` 的全文副本、未登记的归档脚本；提示（NOTICE）列出到期归档与无人引用的 `scripts/slurm/` 作业，清理时按第 2 节处置。
4. 一批清理一次提交。最终回复列出删除与移动的类别、数量和取回方法。

## 5. 取回已删除文件

```bash
git log --diff-filter=D --format='%h %ad' -1 -- <路径>   # 删除所在提交
git show <提交>^:<路径>                                  # 删除前全文
```
